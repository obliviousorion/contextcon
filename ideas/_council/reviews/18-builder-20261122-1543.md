## Top-3 concerns
1. **The reuse claim is not credible as stated.** §13 says it reuses AsOf's attest/resolve engine, outbox and per-tenant design "wholesale" — but per round2-brief-and-data-check.md, that engine is "designed but not built" (only the Crustdata client with cache/replay/ledger/resume is tested so far). LaneBook can inherit the generic client plumbing, not a finished attest/outbox engine, because none exists yet. Effectively LaneBook must build AsOf's core *plus* its own layer in the same window.
2. **Scope is additive, not reused, on top of an unbuilt base.** criterion validator, settle()-as-attest, outbox/approval wiring, LMSR pricing, multi-desk budget split — that's a 6-stage build list (§13) stacked on a foundation that doesn't exist yet, inside a build day already shared with AsOf. The safe cut-lines (drop multi-desk split, flat price instead of LMSR) help, but even the "never cut" list (validator, refusal-first settle, outbox) duplicates AsOf's hardest pieces from scratch.
3. **One live-data dependency is still unverified**: the `settle()` web-sourced path costs "1 + UNVERIFIED" (web fetch credit cost never measured) — same open risk AsOf already flagged and left open. `job/search` also returned HTTP 400 in the live check and is not fixed.

## Fatal flaws
None outright — no disabled endpoint is used (all calls route through identify/search/enrich/web/watchers, all enabled), and cut-lines are sane. The risk is time, not data access: a small team building this *as well as* AsOf's core in the hours left to code freeze risks shipping neither cleanly.

## Cheapest live check (≤10 credits) to de-risk
One recorded web search + one web fetch against a page already known to carry a dated, checkable fact (e.g. a Delhivery or TCI Express press/filing page) — **≈2 credits**. This measures the real web-fetch credit cost (currently UNVERIFIED for both AsOf and LaneBook) and confirms a fetched page returns an exact dated passage, the thing `settle()`'s web-sourced criterion path depends on. Run in `MODE=record`, commit the fixture. Skip a separate `job/search` fix-and-call; it's not on LaneBook's critical path.

## Recommended merges/changes
- Rewrite §13 to say LaneBook **shares the Crustdata client (cache/replay/ledger/resume) with AsOf**, not "reuses AsOf's attest/resolve engine wholesale" — the latter doesn't exist to reuse yet. State the real incremental build: validator + settle (attest-shaped) + outbox + flat-price market, all built new, informed by AsOf's design doc.
- Cut LMSR entirely for the MVP demo; a flat/fixed price with the "aggregated estimate" label meets every demo and ethics requirement without the pricing-math risk. Promote this from "cut order #2" to "cut on day one."
- Before committing further design time, get explicit team sign-off that LaneBook is sequenced *after* AsOf's core ships (not in parallel), since it structurally depends on AsOf's refusal-first pattern being proven first.
- Flag the "prediction market" framing risk (already noted in §14.1) as a go/no-go gate, not an open risk — if the ethics judge reads it as gambling, the builder cost of the LMSR/trade layer is wasted regardless of code quality.
